# Stage 5 ACS clinical review pack

This pack is a review queue, not executable treatment guidance. Every candidate below is version 1, has the non-clinical guard trigger `governance.stage5_licensed_tested_reviewed == <rule ID>`, and has deliberately incomplete logic: an independent clinical reviewer must author concise licensed logic, exclusions, class/level (where applicable), and expected boundary outputs from the cited source. Machine status remains `draft`; the lifecycle queue state is `CLINICAL_REVIEW`; technical test status is `not_run`. No candidate is published.

Primary evidence: [2023 ESC acute coronary syndromes guideline](https://www.escardio.org/guidelines/clinical-practice-guidelines/all-esc-practice-guidelines/acute-coronary-syndromes/), version/year 2023. Full tables and algorithms are not embedded.

| Rule ID                | Clinical question                                          | Required inputs                                                             | Exclusions / stop conditions                           | Proposed output                     | Boundary tests                                                         |
| ---------------------- | ---------------------------------------------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------ | ----------------------------------- | ---------------------------------------------------------------------- |
| `cad.acs-diagnosis`    | Which ACS working diagnosis is supported?                  | Symptoms; ECG; serial assay-specific troponin; timing                       | Insufficient evidence; alternative diagnosis           | Clinician diagnostic review         | STEMI; NSTEMI; unstable angina; uncertain                              |
| `cad.serial-troponin`  | How should serial troponins be interpreted for this assay? | Assay; value; unit; assay URL; collection times                             | Unknown assay upper reference limit; mixed assay units | Assay-specific review               | Serial rise; stable elevation; unknown reference limit; single sample  |
| `cad.acs-risk`         | Is a validated risk tool applicable and complete?          | Age; heart rate; BP; creatinine; HF; ECG; troponin; arrest                  | Missing score inputs; population mismatch              | Transparent score with missing data | Complete GRACE input; missing input; instability discordant with score |
| `cad.invasive-timing`  | What invasive assessment timing merits clinician review?   | ACS category; instability; ischemia; ECG; troponin; comorbidity             | Unconfirmed category; contraindication not reviewed    | Timing review                       | STEMI; higher-risk NSTE-ACS; uncertain ACS; renal concern              |
| `cad.reperfusion`      | Which reperfusion options require urgent assessment?       | Symptom onset; first contact; ECG; diagnosis; availability                  | Diagnosis unconfirmed; missing timing                  | Urgent clinician pathway review     | Early STEMI; late presentation; uncertain onset                        |
| `cad.acs-complication` | Does a new ACS complication require urgent review?         | Symptoms; ECG; hemodynamics; Echo; haemoglobin; renal function; PCI history | Finding entered in error                               | Clinician escalation review         | Shock; major bleed; mechanical concern; alternative cause              |
| `cad.acs-discharge`    | Which relevant discharge elements remain incomplete?       | Active ACS; PCI; LVEF; medication; renal context; rehabilitation; follow-up | Active instability; item documented as not applicable  | Discharge review gaps               | Uncomplicated PCI; HF; bleeding; staged PCI                            |

ACS antithrombotic review uses the linked candidates `cad.dapt-review`, `cad.pci-anticoagulant`, and `cad.bleeding-risk` in the [PCI / antiplatelet review pack](PCI_ANTIPLATELET_REVIEW_PACK.md). Reviewers must assess these together with the ACS candidates before any publication.

Review completion requires licensed source extraction, explicit expected outputs for every boundary, independent maker/checker approval, a separate passing test run, and publication through the existing governance service. An implementation account cannot satisfy those gates.
